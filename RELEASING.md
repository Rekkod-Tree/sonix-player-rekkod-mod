# Публикация прошивки и OTA

Обновлятор использует GitHub Releases из `ota-repo` в `system-info.json`.
Для HiBy R1 нужен загруженный asset **`r1.upt`**, для другой модели — её
собственное имя. Draft не предлагается. Проверки модели, HTTPS, размера,
SHA-256 и безопасного доступа к карте сохраняются.

## Обычная публикация после исправления OTA

1. Соберите и проверьте нужный образ; возьмите его **внутреннюю версию** из
   `OS_version`/проверенного манифеста сборки.
2. Для запланированного выпуска 1.4.0 используйте тег и название `v1.4.0`.
   Название релиза не обязано совпадать с внутренней версией прошивки.
3. Прикрепите `r1.upt`. Не заменяйте его образом для другой аппаратной модели.
4. Добавьте отдельной строкой в описание, подставив реальную версию:

   ```html
   <!-- Sonix-Version: 1.4.0 -->
   ```

Маркер скрыт при просмотре GitHub, но доступен обновлятору через API. Он должен
быть единственным и соответствовать прикреплённому образу. Описание можно
редактировать, сохраняя эту строку. Если маркера нет, новый обновлятор принимает
полный числовой тег версии; даты публикации и рекламные названия не определяют
порядок обновлений. Считаются поколение UI и номера alpha/beta/rc.

Стабильная установка не переводится автоматически на предварительную версию.
Установка alpha/beta/rc может получать предварительные обновления. Если нет
пригодного нового релиза, а совместимый релиз имеет непонятную версию,
показывается ошибка проверки вместо ложного «обновлений нет».

## Переход со старого обновлятора

Для первой исправленной сборки можно сохранить OTA и на старых клиентах.
Для образа с внутренней версией `1.4.0` используйте числовой тег
**`v1.4.0`**, загрузите `r1.upt`, добавьте приведённый выше маркер и
**не включайте Pre-release**: прежний обновлятор такие релизы пропускает.

Старый алгоритм сравнит числовые части: `1.4.0` новее, чем
`1.3.0-ui3-alpha10`, `1.3.0-ui3-alpha20` и `1.3.0-ui3-alpha25`,
которые он считал `1.3.0.0`. Это три опубликованные версии мода,
для которых требуется сохранить переход на 1.4.0.
После установки новый алгоритм возьмёт `1.4.0` из маркера и не предложит
этот же образ повторно. Отдельный псевдоним вида `1.3.0.26` не нужен.
Далее можно продолжать публикацию с привычными тегами `rN` и маркером.

Это относится к сборкам, где уже есть OTA и указан этот репозиторий. Прошивки
без обновлятора или с другим `ota-repo` потребуют своего переходного пути.

Обычное обновление не требует исправленного recovery. Разовая правка recovery
добровольна и не входит в автоматическую установку. Перед публикацией проверьте
в распакованном **итоговом** `r1.upt` модель HiBy R1, `OS_version=1.4.0`,
`ota-repo=Rekkod-Tree/sonix-player-rekkod-mod`, соответствие SHA-256 и размер
раздела. Проверка выбора версии отдельно от проверки скачивания и установки.

## Соответствие уже опубликованных образов

- `r2`, название `v1.2`: `1.3.0-ui3-alpha25`, SHA-256 начинается с `2f34d80b`.
- `release`, название `v1.1`: `1.3.0-ui3-alpha20`, SHA-256 начинается с `783a03f3`.

Соответствие проверено по полным SHA-256 локальных образов и GitHub assets.
К описаниям добавлены маркеры; теги, названия и бинарные файлы не заменялись.
Сами эти маркеры не меняют код обновлятора в уже установленной alpha25.

# Плагины Compás в Sonix: оценка совместимости

**Статус на 18.10.2026: по решению пользователя поддержку плагинов откладываем.
Новые и существующие функции развиваем нативно в Sonix. Lua runtime, широкий
публичный API, слой совместимости и магазин плагинов сейчас не внедряем.**
Исследование ниже сохранено для справки; оно не является задачей на реализацию.
Возвращение к плагинам требует нового решения пользователя.

Дата: 18.10.2026. **Вывод: поддержку части неизменённых Lua-плагинов добавить
реалистично, сохранив Graphite 2 и существующие функции Sonix. Полная совместимость
со всем каталогом потребует самостоятельной подсистемы, а не копирования загрузчика.**
В текущей прошивке этих плагинов ещё нет. Ни Lua, ни плагины в Sonix в рамках этого
исследования не запускались. Плеер, его настройки и прошивка не изменялись.

указывает API 15, поэтому ориентироваться только на руководство нельзя.

В изученной main каталога **66 пакетов**; 63 допускаются к публикации по правилу
`publish`, где отсутствие поля означает `true`, как в upstream build_index.py.

`tools/compas-audit/inventory-2026-10-18.json`. Четыре теста проверяют игнорирование
комментариев/строк, косвенные обращения, вложенные API и отказ при изменении реестра.
Это **не тест исполнения**: наличие имени функции не доказывает совместимость
аргументов, результата, веток fallback, файлов или побочных эффектов.

## Как устроен Compás

- Lua 5.5.1 встроена в C-программу. Каждый `.lua` непосредственно в `.plugins`
  получает отдельный `lua_State`; одновременно допускаются до 32 включённых
  плагинов. Файлы загружаются по имени, код верхнего уровня выполняется сразу.
- `plugin.define` задаёт ID, версию и `api_min`. `has_capability` проверяет
  отдельные возможности. Простого сравнения `api_min` для переноса недостаточно.
- `register_list_item`, `show_list`, `show_settings_list`, `show_text_input`
  описывают интерфейс на высоком уровне. Lua не получает произвольные указатели
  LVGL; Compás строит экраны сам. Это главная возможность сохранить наш дизайн.
- События воспроизведения, изменения выхода/громкости, сна и таймеры возвращают
  управление Lua. Колбэки и загрузка выполняются в UI-потоке. HTTP async работает
  в рабочих потоках; завершения доставляет `plugin_manager_poll`.
- UI API включает и глобальные изменения: Home, меню, цвета, иконки, экран
  блокировки и XML-макеты плеера. Такие дополнения действительно меняют оформление.
- `storage` и `secrets` привязаны к ID. Есть квоты: 256 КиБ на значение, 2 МиБ
  на плагин и 8 МиБ суммарно. На устройстве каталог — `/usr/data/.compas/plugins`.
- Магазин скачивает каталог и файлы с GitHub, проверяет размер и SHA-256, хранит
  список установленных файлов, учитывает конфликты и дополнительные `dest`.
  Контрольная сумма относительно каталога не является независимой подписью автора.

Проверенные исходники: [менеджер и Lua API](https://github.com/Starnished66/compas-player/blob/20d1446ea24de71a82277a0bf725515e8910d511/src/plugins/plugin_manager.c),
[хранилище](https://github.com/Starnished66/compas-player/blob/20d1446ea24de71a82277a0bf725515e8910d511/src/plugins/plugin_storage.c),
[магазин](https://github.com/Starnished66/compas-player/blob/20d1446ea24de71a82277a0bf725515e8910d511/src/network/plugin_store.c),

## Что можно сохранить в нашем UI

Предлагается собственный адаптер `plugin.*` поверх Sonix. Скрипт описывает
список или настройку; адаптер строит их через `sx_row`, `settingsrow`, `sx_card`,
наш `gridpage`, клавиатуру, шрифты и `switcher`. Статусная строка, мини-плеер,
полный плеер, свайп назад и жесты строк остаются нативными. Размеры и стили
сопоставляются с токенами Graphite, а не копируются из gui_plugins.c Compás.

| Область | Опора в Sonix | Что ещё требуется |
| --- | --- | --- |
| Списки/настройки | `sx_row.h`, `settingsrow.h`, `gridpage.h`, `keyboard.h` | Пул страниц, схемы Lua-строк, callbacks с поколением; индексы Lua начинаются с 1 |
| Навигация | `switcher.h`, player sheet | Возврат из вложенных экранов плагина, удаление страниц без сломанной истории |
| Воспроизведение | `audio.h`, `playlist.h`, `player.h` | Поля состояния, порядок событий, семантика skip/stop и владение очередью |
| Библиотека | `library.h`, `metadata.h` | Пагинация и соответствие Compás-полей; свои ID базы Sonix |
| Сеть | `system/net/http.h`, `gui_post` | Совместимые ответы, методы, headers, отмена и ограниченные задачи; HTTP Sonix блокирует вызывающий поток |
| PEQ/MSEB | `system/audio/eq.h` | Единицы и форматы, пакетное runtime-применение без сохранения, сопоставление bypass |
| Файлы | `system/device/system.h` | Все операции проходят через доступность/владение картой, включая Lua `io` |
| Потоковые источники | `streaming/provider.h` | Отдельный мост remote-метаданных, очереди и жизненного цикла Lua-провайдера |

Нативные Яндекс Музыка, Звук, офлайн-загрузки, книги, прогресс, поиск, очереди,
USB/ADB и звук остаются владельцами своих функций. Плагины добавляют возможности,
а не заменяют эти подсистемы. Плагины Audiobooks/Podcasts/Qobuz/Tidal не включаются
вместо существующих модулей: это дублирование и отдельные форматы состояния.

Иконки Compás используют другие пути ресурсов; потребуется сопоставление с нашими
иконками либо корректно установленные дополнительные изображения. Общий LVGL этого
не решает. Тексты скриптов также не становятся русскими автоматически. Системный UI
нового менеджера требует переводов во всех языках обеих наших overlay-сборок.

## Практическая матрица переноса

Ни один пакет пока не объявляется готовым к установке в Sonix. Ниже — оценка
зависимостей, а не результаты работы на R1.

| Пакет/семейство | Оценка | Главная зависимость/ограничение |
| --- | --- | --- |
| Track Inspector | Хороший первый кандидат | Нативный Graphite-экран и read-only сведения; неизвестное выводить неизвестным, без ложного «bit-perfect» |
| Album Shuffle | Реалистичный пилот | Библиотека, альбомный порядок и событие `queue_exhausted`; не перехватывать очередь книги/стриминга |
| Lyrics Fetcher | Реалистичен после сети/файлов | Async HTTP, progress, сохранение LRC и обновление наших lyrics |
| Cover Art Fetcher | Следующий этап | Доступ к альбомным файлам, резервирование/отмена, обновление нашего cover cache |
| ListenBrainz / Discover | Реалистичны после state/events/storage | Авторизация, ограниченная очередь отправки, сон и восстановление сети |
| Jellyfin / Emby | Возможен, отдельный значительный мост | `play_remote`, `queue_remote_list`, метаданные, seek, списки и отмена запросов |
| AutoEQ | Lua UI переносим, формат требует адаптера | Compás сохраняет `.peq` в `PEQ_Profiles`; у нас уже есть AutoEQ и APO `.txt` в `PEQ` |
| AutoEQ Context / Output-Aware Sound | Только после доработки runtime EQ | `{persist=false}`, baseline/restore и приоритет ручного изменения пользователя |
| MSEB / Sound Profiles / Gain Mode | Не включать автоматически | У нас собственные MSEB/PEQ и шкала громкости; простая подмена setter-ов меняет контракт и звук |
| Extended Sleep Timer / Volume Limiter | После transient-volume API | `silent`, `persist=false`, события громкости; не сохранять промежуточные уровни |
| A–B Repeat / ABX / Metronome | Lua-слоя недостаточно | Нужны нативные loop/AB-switch операции; эквивалентный публичный контракт в Sonix не найден |
| Audiobooks / Podcasts / EPUB Reader | Возможны отдельными функциями | Сначала определить владельца прогресса, очереди и файлов; не терять наш прогресс и сервисные загрузки |
| Темы, Kids Mode, Home/LockScreen | Только отдельный режим настройки UI | Изменяют глобальные экраны; не входят в обещание неизменного Graphite 2 |
| Восемь XML Player layouts | Отдельный проект, не первая версия | Зависимость от XML-движка и именованных виджетов Compás; это не готовые скины Sonix |

## Существенные различия, которые нельзя замаскировать

**EQ.** Compás `.peq` хранит `bypass`, `preamp`, `band0_freq/gain/q/type/enabled`,
стереобазу и crossfeed. Наш APO-файл хранит `Preamp:` и `Filter ...`, а PEQ/MSEB
и стереобаза имеют собственные переключатели. Compás передаёт gain/Q числами,
Sonix — десятыми/сотыми. Нельзя просто переслать значения или тихо обрезать диапазон.

Наши `peq_set_band`/`peq_set_preamp` сохраняют конфиг и забывают имя пресета.
Они не реализуют Compás `eq_apply_state(..., {persist=false})`. Нужны предварительная
валидация всей кривой, атомарное runtime-применение и явное отдельное сохранение.
При ручной коррекции автоматизация прекращает владение; отключение плагина не должно
восстанавливать старый baseline поверх нового выбора пользователя. Body Voice,
MSEB и остальные текущие настройки нельзя менять при простом включении подсистемы.

**Очереди и метаданные.** `play_list`/`play_remote` должны входить в наш путь
воспроизведения, сохраняя название, исполнителя, обложку и смысл «следующим».
`queue_exhausted` отличается от ручного Stop. В Sonix есть shuffle-repeat и
упорядоченные очереди подкастов; Compás-строки режимов не описывают всё наше состояние.
Нативный `stream_provider` регистрируется до GUI и затем неизменяем: выгрузка Lua
потребует безопасной промежуточной записи, а не указателя на уничтоженный lua_State.

**Изоляция.** Отдельные Lua states не являются отдельными процессами. Compás
отключает shell/debug/динамическую загрузку, но оставляет `io.open`, remove/rename
за пределами зарезервированного хранилища. Это нельзя переносить без привязки
доступа к карте и без защиты наших конфигов/ключей. Совместимость старых путей
потребует проверяемого resolver-а или адаптации конкретного Lua-скрипта.

**Зависания и память.** В Compás мягкий лимит Lua-вызова — 2 секунды, жёсткий —
3 секунды; C-время исключается. Синхронный HTTP остаётся способным задержать UI.
Входной allocator — `luaL_newstate`, отдельной квоты Lua heap здесь не найдено;
квоты storage не ограничивают RAM. При hard abort исходник намеренно не закрывает
потенциально повреждённый Lua state. Это веская причина не копировать менеджер целиком.

Нужны квоты Lua allocator-а и нативных буферов, ограниченные очереди задач, отмена,
обработка OOM и блокировки без сетевых ожиданий на UI-потоке. В первой версии
допускать проверенные плагины/версии; строгая изоляция произвольного стороннего кода
может потребовать отдельного процесса. Её не обеспечивает один `lua_pcall`.
Точные бюджеты RAM/времени выбираются по измерениям, которых пока нет.

## Архивный вариант первой версии — не принят к реализации

1. Lua с тем же числовым поведением и версией синтаксиса; сборка сначала только
   для host и отдельного флага. Не заменять main.c, gui.c, аудиодвижок или updater Compás-версиями.
2. Небольшое совместимое ядро: define/capabilities, Graphite-списки/настройки,
   уведомления, события, read-only состояние, ограниченные storage/timers.
   LVGL доступен только UI-потоку через наш мост `gui_post`.
3. Проверить неизменённые, зафиксированные по SHA Lua-файлы Track Inspector и
   Album Shuffle. Затем отдельно добавлять сетевую часть на Lyrics Fetcher.
   Совпадение исходного SHA плюс контрактные и сценарные тесты отличает
   «используем готовый плагин» от «портировали его функцию».
4. В менеджере явно указывать поддерживаемый профиль и проверенные версии.
   Не объявлять полную Compás API 16 и не подменять отсутствующие функции no-op-ами.
   `api_min=16` — необходимая метка ревизии контракта, не сертификат совместимости.
   Неизменённый скрипт допускается только после реализации всех его реально
   необходимых контрактов; пока это не доказано, пакет остаётся недоступным.
5. Магазин — после runtime: отдельная проверяемая установка с размером/хешами,
   staging/rollback, учётом файлов и свободного места. Сначала локальная установка
   нескольких проверенных пакетов; весь внешний каталог автоматически не включать.

До первого запуска на R1 нужен доступный при загрузке режим без плагинов и
возможность исключить неудачно включённый пакет. Загрузка/отключение плагина —
транзакция регистрации: ошибка удаляет его страницы, callbacks и задачи,
сохраняя нативные экраны и очередь. Кэширование совместимости привязывается к
ID, версии и SHA файлов; обновление плагина требует повторной проверки, а не
автоматического наследования допуска. Цена boot-маркеров и журналирования также
входит в бюджет записей; журнал каждого callback не нужен.

Неподдерживаемая функция/версия должна дать явную ошибку менеджера, не исчезнувшую
кнопку и не частично применённый EQ. Допустимые fallback-ветки проверяются отдельно.

## Как доказать сохранение UI, функций и надёжности

| Сценарий | Требуемый результат |
| --- | --- |
| Подсистема включена, плагины выключены | Сохранились страницы Graphite, жесты, наш Home, настройки и звук; сравнены кадры и config без служебных времён |
| Plugin list/settings → вложенная страница → Back/плеер | Наши шрифты/отступы/компоненты; назад и player sheet работают; callback относится к выбранной строке |
| Локальный альбом, файлы, shuffle, «следующим» | Плагин не теряет очередь/историю; Album Shuffle запускается только по явному действию, не в книге |
| Яндекс/Звук и офлайн-книга | Названия/обложки, загрузки, прогресс и продолжение нативных модулей сохранены |
| Ошибка Lua/OOM/долгий callback/несколько таймеров | Плагин останавливается с причиной; UI, audio и выход из него остаются работоспособными |
| Disable/reload во время HTTP и открытого экрана | Отмена/снятие callbacks, tokens поколения; поздний результат не обращается к закрытой VM или старой странице |
| Нет сети, SD заполнена/извлечена/передана по USB | Ошибка без записи в пустой mountpoint; файлы/настройки остаются целыми; операции имеют ограниченное завершение |
| Авто-EQ → ручной выбор Body Voice → Disable | Новый ручной выбор остаётся, промежуточные состояния не записаны как постоянные |
| Сон, пробуждение, выключение и повторные reload | Нет активных фоновых запросов/таймеров без необходимости; проверены RAM, утечки, wakeups и расход записи |

Дополнительно: host/target/ABI-проверка, LTO/O3, пересмотр применимости PGO после
нового кода, аппаратный прогон на R1. Нагрузка измеряется относительно той же
прошивки без включённых плагинов: RSS, CPU, frame latency, underruns, время запуска,
записи на карту и standby. Проценты ускорения/замедления и время работы батареи
сейчас неизвестны. Новый Lua-слой не является оптимизацией звукового тракта.

## Решение

**Текущее решение пользователя: обойтись без плагинов и разрабатывать нужные
функции нативно.** Нативные модули сохраняют существующее владение UI, звуком,
очередями, картой, сервисами и прогрессом. Ничего из уже работающего не требуется
выносить в плагины или дублировать ими.

Причины отсрочки: не подтверждён внешний спрос, неизвестна стоимость runtime по
памяти/CPU/батарее, а совместимость с чужим API создаёт постоянные обязанности
по сопровождению. Результаты исследования и статический хелпер остаются в
репозитории. Загрузчик, Lua runtime, API и host-пилот не реализуются в рамках
текущей задачи. Плеер и прошивка не менялись.

Лицензии Sonix/Compás/каталога: GPLv3; атрибуцию переносимого кода необходимо
сохранить. Lua поставляется со своей лицензией. Стоковые ресурсы HiBy не следует
копировать в Git вместе с адаптером. Ссылки на upstream закреплены выше.

Повтор статической инвентаризации, без исполнения Lua:
